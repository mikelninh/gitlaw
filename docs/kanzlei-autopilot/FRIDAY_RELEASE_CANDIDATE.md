## What Bao should bring

Minimum — enough for a successful meeting:

- laptop with normal Kanzlei access
- one ordinary, representative, non-emergency matter
- a rough estimate of how long he normally spends on: understanding changes, missing documents, timeline reconstruction, deadline triage, next-action preparation
- ability to produce a redacted/local CSV or manually inspect the matter in Advoware

Optional — unlocks live read-only Advoware sync:

- Advoware Kanzleikennung / endpoint context
- third-party App-ID and API key made available locally at the meeting

Never paste credentials into GitHub, chat, screenshots or source code.

## One-real-matter rule

Choose a matter that is:

- ordinary and representative
- not an emergency
- not the most sensitive case in the office
- useful for document/status/timeline work

Use a pseudonymous reference such as `matter-shadow-01` in GitLaw measurement surfaces.

Real names, emails, IBANs and confidential narrative belong only in the approved Kanzlei system/local case context, not in the measurement console.

## 60-minute agenda

### 0–10 min — Attack the safety boundary

Run Privacy Proof Center. Required observation: blocked payloads show provider calls = 0.

### 10–20 min — Synthetic golden case

Run Bao Today → case work packet → research/draft/review with synthetic data.

### 20–40 min — One real Shadow matter

### 40–50 min — Inspect first wins

Compare baseline vs pilot vs rework. Do not count negative or unconfirmed savings.

### 50–60 min — Choose Week 01 automation

Rank by:

`weekly minutes × frequency × safe automation potential × confidence`

Promote one bounded action, not a whole vague agent.

## Kill switches / immediate STOP

Stop the real-case pilot immediately if any of these occur:

- unexplained network/provider egress
- wrong-matter or cross-tenant data
- real case treated as synthetic
- external message sent without exact authority
- beA/authority action without Bao approval
- date presented as binding legal deadline without lawyer confirmation
- plaintext real-mandate cloud snapshot
- missing/confusing audit evidence for a consequential action

A STOP is a successful safety result if the system blocks before consequence.
